# QuietWard Response v1.2.0-alpha.1

Status: **candidate — automated finalizer and browser smoke required before tag/publication**

Backend/API version: `1.2.0a1`

## Purpose

v1.2 turns the broad v1.1 response-planning platform into the first alpha with narrowly executable real containment while preserving a fail-closed control plane.

The release remains standalone and does not require Response code in any detector repository.

## New executable capabilities

- bounded read-only host diagnostic;
- bounded read-only process diagnostic with short-lived local process handles;
- exact process termination by opaque handle on Windows/Linux, opt-in per agent;
- bounded managed-file diagnostic with short-lived local file handles;
- managed-file quarantine by opaque handle, opt-in per agent;
- quarantine rollback through a separate rollback handle.

All registered actions require analyst approval and deterministic policy.

## Signed endpoint capability negotiation

A v1.2 Response agent signs its supported and locally enabled action set to:

`POST /api/v1/agents/{agent_id}/capabilities`

The report explicitly attests that arbitrary command execution is disabled. Enabled actions must be a subset of the finite server registry; unknown capabilities are rejected.

Server policy refuses every non-legacy v1.2 action unless the target agent has signed a capability report and that exact action is locally enabled. High-impact capability switches therefore cannot be turned on by the server alone.

The enrollment helper sends the first report immediately. The official poll command refreshes it before every poll:

```text
python scripts/poll_response_agent.py --config PATH_TO_AGENT_JSON
```

The original `response_agent.py poll-once` remains a compatibility/debugging path; the capability-aware wrapper is the qualified v1.2 operating path.

## Agent credential rotation

Agents can rotate their own HMAC credential through a request signed by the current credential:

`POST /api/v1/agents/{agent_id}/rotate-key`

The server returns the new key ID/secret exactly once with no-store headers. The previous key is retained only as a five-minute recovery credential so a failed local config replacement does not permanently strand the endpoint.

Use:

```text
python scripts/rotate_response_agent_key.py --config PATH_TO_AGENT_JSON
```

The helper replaces the private config atomically, verifies the new credential by syncing capabilities, and never prints the new secret. Disabled agents cannot rotate. The previous key is rejected after its grace expiry.

## Resource identity model

The server does not choose raw process IDs or filesystem paths. The Response agent observes local state and creates random opaque handles backed by private local identity/fingerprint records.

Handles are:

- local to the agent;
- incident/host/agent provenance-bound;
- expiring;
- single-consumption for mutating operations;
- revalidated against current local identity immediately before mutation.

Process termination/quarantine action TTLs are capped at 240 seconds, below the five-minute diagnostic handle lifetime.

## File safety

File containment is restricted to configured managed roots. Symlinks are excluded. The quarantine directory must be outside managed roots. File identity includes metadata plus SHA-256 content. Quarantine revalidates identity and verifies content after the move, then returns rollback metadata/handle. Restore fails if the original path is occupied, escapes the managed root, or the quarantined object changed.

The remaining local-filesystem limitation is a same-user race between final identity verification and the filesystem move on platforms that do not provide a portable atomic verify-and-move primitive. The executor narrows this with inode/device/metadata/content checks and post-move verification; future platform-specific hardening can use stronger descriptor/handle-relative primitives where available.

## Process safety

The process executor protects the Response agent, its parent, low/system PIDs and critical Windows process names. Process identity includes creation/start data beyond PID. Linux uses pidfd-bound signaling and verifies the exact identity exited; Windows revalidates process creation identity on the termination handle and waits for bounded exit. Stale/replaced process identities fail closed. Interrupted termination with an indeterminate outcome fails closed rather than claiming success.

## Analyst authentication

Loopback development retains the historical local actor-header convenience.

Non-loopback or non-development Response requires hashed bearer credentials configured through `QWR_ANALYST_CREDENTIALS` with roles:

- viewer;
- responder;
- admin.

Authenticated identity controls audit attribution and cannot be replaced by a spoofed `X-Actor-ID`.

Use `scripts/generate_analyst_token.py` to generate a high-entropy token and its SHA-256 configuration entry.

## Signed audit checkpoints

v1.2 can export an HMAC-signed audit-head checkpoint at:

`GET /api/v1/audit/checkpoint`

and verify a retained checkpoint at:

`POST /api/v1/audit/checkpoint/verify`

The checkpoint signing secret is independent from the database and must be replaced outside loopback development using `QWR_AUDIT_CHECKPOINT_SECRET`.

If a checkpoint is retained outside the Response database, later verification detects:

- tampering that breaks the ordinary audit hash chain;
- an attacker consistently rewriting/re-hashing the entire historical chain after the checkpoint;
- deletion/truncation of audit records that were already covered by the checkpoint;
- checkpoint signature tampering.

This strengthens tamper evidence but does not claim immutable/WORM external logging. Checkpoint security depends on external retention of the checkpoint and protection of the independent signing secret.

## Abuse resistance

- configurable request-size cap;
- configurable per-client `/api/v1` request-rate cap;
- 413/429 fail-closed responses;
- no-store/security headers;
- bounded ActionResult/evidence sizes retained from v1.1;
- high-impact action TTLs shorter than diagnostic-handle lifetimes;
- normal UI offers only unexpired handles returned by successful prior actions for the same incident and selected agent rather than free-form PID/path/handle input;
- signed endpoint capability state is visible in the Agents console.

## Still not executable

- generic shell/PowerShell/cmd/bash or script execution;
- raw PID/path targeting;
- firewall/network-rule changes or host isolation;
- account/session mutation;
- persistence mutation;
- container stop/remove;
- general service control;
- package/configuration mutation;
- autonomous or model-generated remediation.

## Qualification

```text
python scripts/finalize_v12_alpha.py
```

The wrapper runs static/local qualification and a capability-aware live disposable containment gate. The live gate uses only temporary managed files and a child process it creates itself.

Then perform the browser smoke in `docs/V12_ALPHA_ACCEPTANCE.md` on the exact candidate SHA.

The alpha must not be tagged or published unless both gates pass.
